# Dalil V4: grounded conversational AI layer

| Version | Role | Runtime |
|---|---|---|
| V2 | research baseline: full multilingual transformer embeddings | `DALIL_RUNTIME=full` |
| V3 | lightweight production retrieval (static vectors + lexical + title), no torch | `DALIL_RUNTIME=lite` |
| V4 | V3 retrieval + action-aware rerank + **optional** Gemini layer for language | `DALIL_RUNTIME=v4` (default) |

**Gemini writes language from retrieved evidence. It is NOT treated as an official government source.**
Every fact in a V4 answer comes from Dalil's indexed official pages, and every URL comes from Dalil's records.

## Pipeline (`src/v4/engine.py`)
1. **Redact** obvious identifiers (ID/iqama numbers, card numbers, IBAN, OTP, passport codes) before any AI call (`src/v4/redact.py`).
2. **Retrieve with V3**, plus the follow-up context (`context_service_id`) and an **action-aware rerank**
   (`src/v4/actions.py`: issue/register, reserve, renew, cancel/delete, modify, transfer, inquire, replace-lost,
   pay, unlock, object, extract; English and Arabic). The rerank weights (bonus 0.02, penalty 0.03) were chosen
   on dev+val. Reranking can only reorder candidates: the decision score is still the raw V3 score.
3. **Gemini call 1, only when needed** (top score below the answer threshold, or a conversation or
   follow-up): returns intent/action, an in-scope flag, whether the question refers to the previous service,
   and 3–5 Arabic/English search variants. Variants must beat the user's own wording by 0.03.
4. **Deterministic sufficiency** with V3's calibrated thresholds: answer, possible match, related links, or
   insufficient. Gemini can *downgrade* (out of scope, or the evidence is about another service) but never
   upgrade.
5. **Gemini call 2:** answer only from a compact package of 1–3 services, built only from fields present
   in the records, with evidence ids such as `S1.fees`.
6. **Validation:** every point must cite valid evidence ids. Any number in a point must appear in the cited
   evidence. Text containing a URL is rejected. The answer must be in the right language. Points that fail
   are dropped; if nothing valid remains, Dalil returns the V3 answer (verbatim official text).
   - Missing intent fields (fee, documents, time, requirements) are listed in `unverified_information`:
     "Dalil could not verify …".
7. **Fallback:** no key, timeout, 429/403 quota, network or HTTP error, bad JSON or ungrounded output all
   return the V3 answer. The API keeps working.

## API (`POST /ask`, backward compatible)
- New optional request fields:
  - `conversation_context`: up to 8 turns, `{role: user|assistant, text}`.
  - `use_ai`: `false` forces the deterministic answer.
- New response fields:
  - `response_mode`, `answer`, `text_origin`
  - `ai_enabled`, `ai_used`, `ai_model`, `ai_fallback_reason`
  - `verified_fields`, `unverified_information`, `follow_up_suggestions`
  - `search_queries`, `redactions_applied`
- `sources[].url` always comes from the records.

## Configuration
- `GEMINI_API_KEY`: server-side environment variable only. It is never logged or returned, and is sent only
  as the `x-goog-api-key` header.
- `GEMINI_MODEL`: default `gemini-3.5-flash-lite` (stable, free tier).
- `GEMINI_TIMEOUT_SECONDS`: default 20.
- `DALIL_AI=off` disables the AI layer.
- No new dependencies: the client uses Python's standard `urllib`.
- PythonAnywhere free accounts can reach `*.googleapis.com` (it is on their allowlist).

## Evaluation
- Deterministic retrieval: `python -m src.evaluation.evaluate_v4` writes `results_v4.json`.
  - Same benchmark, split and V3 thresholds.
  - Test Top-1, Top-3 and MRR are unchanged (77.5 / 89.2 / 0.839).
  - Unsupported refusal stays at 81.0% and unsupported confident answers at 4.8%.
  - Confident precision drops from 97.7% to 95.5%, because one Hajj "status" question was reranked to the
    booking service.
  - On manual action-confusion checks, «كيف أطلع سجل تجاري», «ابغى افتح سجل تجاري», «كيف أستخرج سجل تجاري
    لمؤسسة فردية» and "register a business" moved from the deletion, update or unlock service to the
    commercial-registration service. "Get a commercial registration" still ranks "Query about commercial
    registration data" first.
- Grounded AI with the real API (`gemini-3.5-flash-lite`, free tier):
  - First full run (`results_v4_ai.json`, 23 questions, 40 calls): only 6 AI answers. 78 of 136 proposed
    points were rejected. Diagnosis: whole answers were rejected because the validator required one exact
    evidence-id format, plus Arabic answers hit `bad_json`. No individual unsupported claim was found in any
    answer.
  - Fix, applied generally:
    - Evidence ids are normalised (`S1.fees`, `[S1:fees]`, a string instead of a list, bare `S1`). Number
      and URL checks still apply against the cited official text.
    - "Evidence doesn't answer" now leads to related links.
    - Malformed JSON is retried once.
  - Re-check sample (`results_v4_ai_sample.json`, 10 questions, 17 calls):
    - 2 of 73 proposed points rejected.
    - All URLs came from the records; the language was right in 10/10.
    - 0 unsupported questions answered.
    - 0 gap questions answered: iqama, driving licence and the injection prompt got related links, not
      invented procedures.
    - Follow-ups «كم الرسوم؟» and «وش المطلوب؟» stayed on mc-1.
    - 1 Arabic answer still failed with malformed JSON (fixed afterwards by the retry; the retry was not
      re-measured with the real API).
  - `partial_answer` was 0 in the sample because every answer there either had the requested field in its
    evidence or was a possible match. The path is covered by a mocked test: a fee question whose evidence
    lacks a fee returns `partial_answer` with "Dalil could not verify the current fee…".

## Limitations
- The validator checks citations, numbers and URLs mechanically. It cannot prove every paraphrase is faithful.
  The evaluation samples are for human review.
- Coverage gaps remain: iqama, traffic fines, driving licences and passports. V4 says it cannot verify these
  rather than answering.
- An official live-source fallback is left for a future V4.x.

## V4.1: official coverage expansion (Absher)
- **Source:** the public Absher e-services user guide on absher.sa (Ministry of Interior). It covers the
  Passport and Traffic sectors for individuals, plus the Absher Business guide for establishments, in
  English and Arabic.
  - Captured by plain GET (`python -m src.ingestion.capture_absher`), with no login and no anti-bot bypass.
  - Parsed by `src/ingestion/absher_guide.py`.
  - Added to the existing knowledge base with `python -m src.ingestion.pipeline --add-absher`, because the
    other sources' raw captures are gitignored.
  - Record IDs are `absher-*`. Text is stored verbatim; empty guide fields stay empty.
  - `absher.sa` was added to the official-domain allowlist.
- **Not used:** my.gov.sa (Cloudflare block) and moi.gov.sa (no response). Neither was bypassed.
- **Size:** 799 → 910 services (+111): 69 bilingual, 2 English-only, 22 Arabic-only, 18 Absher Business.
- **Coverage now includes:**
  - iqama issuance and renewal (establishment and individual), resident ID expiry query
  - traffic violation query, dispute and payment-deadline extension
  - driving licence issuance, renewal and query
  - Saudi passport issuance, renewal, lost-passport replacement and loss reporting
  - exit/re-entry and final-exit visas (issue, cancel, extend, status)
  - vehicle registration (Istimara) renewal and printing
- **Gaps** (no official page captured): replacing a lost iqama, and replacing a lost or damaged driving
  licence. Dalil shows related links instead of answering.
- **Safety rule added:** when the question asks for a clearly different action than the top service
  (for example "lost X" against an "issue X" service), Dalil shows it as a possible match, never as a
  confident answer.
- **Lexicon:** general vocabulary added for driving licence, traffic violations, Istimara, exit/re-entry,
  final exit and lost (فقدت…).
- **Targeted questions** (17, deterministic; `results_v41_coverage.json`): correct Top-1 0 → 11 and
  Top-3 0 → 13 of the 13 coverable. The 4 gap questions stay safe (no confident answer).
- **Held-out benchmark** (unchanged questions and labels):
  - Top-1 77.5 → 76.7%, Top-3 89.2 → 86.7%, MRR 0.839 → 0.829.
  - Confident precision 93.3 → 93.0%.
  - Unsupported questions answered confidently: 1/21 → 1/21.
  - Some questions labelled "unsupported" (exit/re-entry, iqama renewal, licence renewal) are now
    genuinely covered.
